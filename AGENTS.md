# Repository Guidelines

## Project Structure & Module Organization

- `src/main.rs`: binary entry point (GPUI app bootstrap + keybindings).
- `src/app.rs`: core application state and orchestration.
- `src/ui/`: UI components and layout (`conversation`, `sidebar`, `settings_panel`, widgets in `src/ui/widgets/`).
- `src/providers/`: provider registry + HTTP gateway integrations.
- `src/session/`: session model, persistence, and storage format.
- `screenshots/`: documentation images used by `README.md`.
- `target/`: local build output (generated by Cargo; do not commit).

## Build, Test, and Development Commands

- `cargo run`: build and launch the desktop app.
- `cargo build --release`: optimized build in `target/release/`.
- `cargo test`: run unit tests (most tests live in `#[cfg(test)]` modules under `src/`).
- `cargo fmt`: format Rust code with `rustfmt`.
- `cargo clippy --all-targets`: lint and catch common Rust issues.

## Coding Style & Naming Conventions

- Rust 2024 edition (`Cargo.toml`); prefer idiomatic Rust and standard library types.
- Formatting: run `cargo fmt` before pushing.
- Naming: `snake_case` for modules/functions, `CamelCase` for types, `SCREAMING_SNAKE_CASE` for constants.
- Keep UI changes localized to `src/ui/` and avoid large refactors without a clear reason.

## Testing Guidelines

- Add focused unit tests alongside the module being changed (use `mod tests { ... }` with `#[test]`).
- Prefer deterministic tests; avoid network calls. If needed, inject dependencies or use temp dirs (`tempfile` is available).
- Run `cargo test` before opening a PR.

## Commit & Pull Request Guidelines

- Commit messages follow a Conventional Commits-style prefix seen in history: `feat: ...`, `refactor: ...`, `perf: ...`, `chore: ...`.
- PRs should include: a short description, rationale for behavioral changes, and screenshots for UI updates.
- Link related issues and call out any new env vars/config keys.

## Configuration & Secrets

- Provider credentials are read from environment variables (e.g. `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GEMINI_API_KEY`/`GOOGLE_API_KEY`).
- Local config lives in the OS config directory under `aui/` (e.g. `%APPDATA%\\aui\\config.toml` on Windows). Sessions are stored in `aui/sessions/`, logs in `aui/aui.log`.
